# KOSMOS Haiku 5.5 파일럿 — 실험 설계 (사전등록)

- 작성일: 2026-11-05
- 목적: 오픈웨이트 2B~8B 결과(하한선)와 경량 프론티어 모델(상한선)을 같은 문항·같은 프롬프트로 비교한다.
- 원칙: 이 문서를 **결과를 보기 전에** 레포에 커밋하고 커밋 해시를 기록한다. 게이트 기준·지표·해석 규칙은 결과를 본 뒤 바꾸지 않는다. 바꿔야 하면 변경 이력과 이유를 이 문서 끝에 추가한다.

---

## 1. 연구 질문과 가설

**RQ.** 오픈웨이트 모델에서 관찰된 위치 오차, 모드 붕괴, 화계 효과 부재는
(a) 모델 체급의 한계인가, (b) LLM으로 한국인 설문 분포를 재현하는 것 자체의 한계인가?

| 가설 | 내용 | 판정 |
|---|---|---|
| H1 (위치) | Haiku의 C0·adult 분포가 균등 기준선과 오픈웨이트(보정 전)보다 KGSS 모집단 분포에 가깝다 | Gate 1 |
| H2 (서브그룹) | 성별×연령 페르소나를 주면 실제 서브그룹이 모집단에서 벗어나는 방향으로 응답이 움직인다 | Gate 2 |
| H3 (화계·인칭) | 민감 문항의 바람직성 편향이 해라체·3인칭에서 달라진다 | Gate 3 (Gate 1 통과 시에만 확증 분석) |

## 2. 재료 (팀장 확장 라운드와 동일)

- **문항:** 확장 라운드 250문항 그대로. 가치관 186(민감 29, 비민감 157) + 차별 17(전부 민감) + 사실 47. 민감 문항 46개.
  - 문항 ID, 문항 텍스트, 보기 번호 매핑은 팀장 `probes.csv`에서 복사한다. 새로 만들지 않는다.
- **정답지:** KGSS 2023 개인 응답 원자료.
  - `Q_pop`: 모집단 분포 (C0, adult 비교용)
  - `Q_c`: 성별×연령 셀 분포 (demo 비교용, n≥20, 미달 시 팀장 백오프 규칙 그대로)
  - 개인 응답: NLL 계산용
- **페르소나:** 성별 2 × 연령 7(22·30·40·50·60·70·80세) = 14명. 텍스트는 팀장 격자와 동일.
- **조건:**

| 조건 | 구성 | 프롬프트 수 |
|---|---|---|
| C0 | 역할 없음 | 250 |
| adult | 한국 성인 × 인칭 2 × 화계 2 | 1,000 |
| demo | 성별×연령 14명 × 인칭 2 × 화계 2 | 14,000 |
| 합계 | | 15,250 (팀장과 동일) |

- **프롬프트:** 오픈웨이트 실험에 넣은 user 텍스트를 **글자 하나 바꾸지 않고** 사용한다.
  - 추가하는 것은 system 메시지 한 줄뿐이다: `보기 번호 숫자 하나만 출력하고 다른 말은 하지 마십시오.`
  - 이 차이는 한계로 기록한다(7절).

## 3. 모델과 호출 설정

| 항목 | 값 | 이유 |
|---|---|---|
| 모델 | **Claude Haiku 5.5** (정확한 모델 ID 고정, 기록) | Haiku 4.5는 10배 비쌈 |
| temperature | 1.0 | 분포를 보는 실험이라 0 금지 |
| top_p / top_k | 기본값 (지정하지 않음) | 분포 왜곡 방지 |
| extended thinking | 끔 | 한 글자 응답, 비용·변동 증가 방지 |
| max_tokens | 5 | 숫자 하나 + 여유 |
| prefill | assistant `정답: ` (Stage 0에서 지원 확인, 미지원 시 정규식 파싱) | 오픈웨이트 completion 형식과 최대한 맞춤 |
| 샘플링 | **호출 1회 = 표본 1개** | Claude API에는 n 파라미터 없음 |
| 처리 | Message Batches API | 50% 할인 |

- **금지:** "답 20개를 한 번에 써라" 같은 방식. 독립 표본이 아니다.
- Claude API는 logprobs를 주지 않으므로 이 실험은 **샘플링 기반 분포 추정**이다.

## 4. 표본 크기와 비용

| 단계 | 내용 | 프롬프트 수 | k (샘플/프롬프트) | 호출 수 |
|---|---|---|---|---|
| Stage 0 | 스모크 테스트: 20문항 × C0·adult | 100 | 20 | 2,000 |
| Stage 1 | H1: 250 × (C0 + adult 4조건) | 1,250 | 50 | 62,500 |
| Stage 2 | H2·H3: 250 × demo 4조건 × 14명 | 14,000 | 20 | 280,000 |
| 합계 | | | | 344,500 |

- **k 근거:** demo는 문항×조건당 14명 × 20 = 280개 표본. 비율 0.3 기준 셀 하나의 SE ≈ 0.10, 14명 합산 시 ≈ 0.03. TVD 추정 노이즈가 오픈웨이트 보정 전후 차이(0.1 이상)보다 충분히 작다. DiD 검정력은 k보다 **문항 수**(민감 46 vs 비민감 204)에서 나오므로 k를 더 올려도 이득이 작다.
- **비용 (공식 요금표, Haiku 5.5 배치: 입력 $0.05/M, 출력 $0.25/M):**
  - 입력: 344,500 × 500토큰 ≈ 1.7억 토큰 → 약 $8.6
  - 출력: 호출당 약 3토큰 ≈ 100만 토큰 → 약 $0.3
  - **합계 약 $9** (프롬프트 토큰 수는 Stage 0 실측값으로 재계산)

## 5. 지표 (오픈웨이트와 정의를 똑같이)

| 지표 | 정의 | 비고 |
|---|---|---|
| 유효율 | 파싱 결과가 해당 문항 보기 범위 안의 숫자인 비율 | mass의 샘플링 버전. 무효는 거부 / 설명문 / 범위 밖 숫자로 나눠 집계 |
| 분포 추정 | 유효 응답 카운트 + Jeffreys 스무딩 α=0.5 | NLL에서 log(0) 방지. 사전 고정 |
| TVD, W1 | 모델 분포와 `Q_pop`/`Q_c` 사이 거리 | W1은 보기를 순서형으로 취급 |
| 개인 NLL | KGSS 개인 실제 응답에 대한 음의 로그우도 | 기준선: 균등분포(하한), `Q_pop` 자체(상한) |
| 최빈값 일치율 | 모델 최빈값 = 인간 최빈값인 문항 비율 | |
| subgroup r | 문항별로 14셀에서 `(P_c − P_adult)`와 `(Q_c − Q_pop)`의 상관, 문항 중앙값 | 오픈웨이트는 0.00~0.14 |
| 타겟 정렬 이득 | `TVD(P_c, Q_pop) − TVD(P_c, Q_c)` | 양수면 모델이 서브그룹 정보를 담고 있음. 오픈웨이트는 약 0 |
| 바람직성 이동 `ds` | 팀이 확정한 바람직한 방향의 확률 초과분 | 방향 확정 전에는 계산하지 않음 |

- **집계 순서:** `avg`(예측 먼저 평균 후 거리)와 `ind`(개별 거리 후 평균) **둘 다** 저장하고 보고한다. 집계 효과 착시를 반복하지 않기 위함.
- **공정 비교 장치 1 (노이즈 매칭):** 오픈웨이트는 정확한 로짓 분포, Haiku는 표본 카운트라 노이즈가 다르다. 오픈웨이트 로짓 분포에서 같은 k만큼 다항 샘플링하고 같은 스무딩을 적용한 버전을 함께 계산해 비교한다.
- **공정 비교 장치 2 (보정 조건 맞춤):** Haiku는 온도 보정을 하지 않는다. 주 비교는 **오픈웨이트 보정 전 vs Haiku**이고, 오픈웨이트 보정 후 수치는 참고로만 둔다.
- **비교 대상:** 10/10 재실험 수치(29문항 기반)가 아니라 **확장 라운드 250문항 오픈웨이트 결과**와 비교한다. 문항과 프롬프트가 같아야 비교가 성립한다.

## 6. 게이트와 판정 규칙 (사전 고정)

### Gate 0 — 형식 (Stage 0)
- 통과 기준: 조건별 유효율 ≥ 95%.
- 미달 시: system 문구와 prefill만 수정하고 재실행한다. 문항과 페르소나 텍스트는 수정하지 않는다.
- 거부율은 민감/비민감 문항별로 기록한다. 3인칭에서 유효율이 떨어지는지도 확인한다(EXAONE 7.8B의 mass 하락과 비교).

### Gate 1 — 위치 (Stage 1)
다음 두 조건을 **모두** 충족하면 통과.
- (a) C0와 adult 각각에서 문항 NLL < 균등 기준선 NLL인 문항 비율 ≥ 70%.
- (b) adult 평균 TVD가 확장 라운드 오픈웨이트 4종 중 최선값(보정 전, 노이즈 매칭 버전)보다 낮고, 문항 클러스터 부트스트랩(2,000회) 95% CI가 0을 넘지 않는다.

### Gate 2 — 서브그룹 (Stage 2)
- 통과 기준: subgroup r 문항 중앙값 > 0.2 이고, 셀 라벨 순열검정(2,000회) p < 0.05.
- 보조: 타겟 정렬 이득 > 0.

### Gate 3 — 화계·인칭 (Stage 2)
- **Gate 1 통과 시에만 확증 분석으로 보고한다.** 미통과 시 탐색적 분석으로만 보고한다.
- 주 분석:
  - 화계 DiD = [(해라체 − 하십시오체)민감 − (해라체 − 하십시오체)비민감]
  - 인칭 DiD = [(3인칭 − 2인칭)민감 − (3인칭 − 2인칭)비민감]
  - 결과 변수: TVD(항상), `ds`(방향 확정 후)
  - 추론: 문항 클러스터 부트스트랩 2,000회, BH 보정
- 보조 분석: demo 민감 문항에서 `화계 효과 ~ 페르소나 연령` 회귀 (고령 × 해라체 화용 부조화).
- 동등성 검정(TOST): 동등성 범위 δ = TVD 0.02로 사전 고정. **Gate 1 미통과 모델에는 TOST를 결론으로 쓰지 않는다.** 측정 불가와 효과 없음을 구분할 수 없기 때문이다.

### 결과 해석표 (미리 고정)

| 결과 | 해석 |
|---|---|
| Gate 1·2 통과 + Gate 3 효과 있음 | 화계·인칭 조작은 작동한다. 오픈웨이트의 실패는 체급 한계다. 하한선(오픈웨이트)과 상한선(Haiku) 사이에 역량 문턱이 있다. |
| Gate 1·2 통과 + Gate 3 효과 없음 | 체급을 올려도 화계·인칭 효과는 무시할 수준이다. 이 경우에만 TOST 결론이 정당하다. |
| Gate 1 통과 + Gate 2 미통과 | 모집단 분포는 맞추지만 서브그룹 정보는 담지 못한다. 페르소나 조건화의 한계. |
| Gate 1 미통과 | 경량 프론티어도 한국인 분포를 재현하지 못한다. 체급만의 문제가 아니다. 중간발표의 "모델이 작아서" 지적에 대한 직접 답변이 된다. |

어느 결과가 나와도 발표 가능한 결론이 된다. 이것이 이 설계의 핵심이다.

## 7. 교란 통제와 한계 (미리 기록)

- **학습 오염:** KGSS 2023 공개 집계가 학습 데이터에 포함됐을 수 있다. 보조 점검으로 문항 10개에 대해 "KGSS 2023에서 이 문항의 응답 비율은?"을 직접 물어 공개 수치를 재현하는지 본다. 재현하면 해당 문항에 플래그를 단다. 완전한 해결책은 아니므로 한계로 명시한다.
- **거부 편향:** 민감 문항에서 거부가 몰리면 유효 응답만으로 만든 분포가 편향된다. 거부율 자체를 결과로 보고하고, 거부를 별도 범주로 두는 민감도 분석을 추가한다.
- **프롬프트 형식 차이:** system 메시지 한 줄과 chat 템플릿 차이가 있다. 오픈웨이트와 완전히 같은 입력이 아님을 기록한다.
- **비결정성:** API는 시드 고정이 불가하다. 모델 ID, 실행 날짜, 파라미터를 기록하고 원문 응답을 전부 보존해 재분석할 수 있게 한다.
- **로짓 vs 샘플링:** 추출 방식이 다르다. 5절의 노이즈 매칭으로 보완하되 한계로 명시한다.
- **바람직한 방향:** 연구자 가정이다. 팀원 개별 검토 후 합의로 확정하며, Haiku 결과를 보기 전에 확정한다.

## 8. 실행 순서 (Argon 작업 지시용)

1. 이 문서를 `research/preregistration_haiku_pilot.md`로 커밋하고 해시를 기록한다.
2. 팀장 `probes.csv`, 페르소나 텍스트, KGSS 정답지를 읽어 프롬프트 15,250개를 생성한다. 오픈웨이트 입력과 user 텍스트가 바이트 단위로 같은지 diff로 검증한다.
3. **Stage 0** 실행 → 유효율, 거부율, prefill 지원 여부, 실제 입력 토큰 수 확인 → 비용 재계산 → Gate 0 판정.
4. **Stage 1** 배치 제출 → 지표 계산 → Gate 1 판정. 통과/미통과와 관계없이 결과를 팀에 그대로 공유한다.
5. **Stage 2** 배치 제출 → Gate 2 판정 → Gate 1 결과에 따라 Gate 3을 확증 또는 탐색으로 보고한다.

### 저장 형식

원문 응답 (`raw/*.jsonl`, 한 줄에 한 호출):
```
model_id, run_date, stage, cond, item_id, persona_id, person, speech,
sample_idx, raw_text, parsed, valid, invalid_type, input_tokens, output_tokens, request_id
```

산출물:
- `counts/`: 문항 × 조건 × 페르소나별 응답 카운트
- `metrics/`: 지표 테이블 (오픈웨이트 4종과 같은 열 구조, `avg`/`ind` 모두 포함)
- `gates.md`: 게이트별 판정과 근거 수치

### 구현 시 반드시 지킬 것
- 파싱 실패를 조용히 버리지 않는다. 무효 유형별로 전부 기록한다.
- 집계 순서 두 가지를 모두 저장한다.
- 게이트 임계값은 코드에 하드코딩하지 않고 설정 파일 한 곳에서 읽는다. 값은 이 문서와 일치해야 한다.
